# 规划代价函数：为什么车「明明能过去就是不走」

2026-09-01 现场。三个独立的错叠在一起，每一个单独都足以让车站住。先排除的：
障碍图**是忠实的**（独立重建逐格对照，2 m 内 mask 99 格 / 重建 83 格，共有 79、多标 20、
漏标 4，逐点净宽两边完全一致），CPU **不是**瓶颈（周期 p50 0.21 s、零丢帧）。

## 1. 承诺段门限把车体半径算了两遍

`_prefix_clearance` 是圆形底盘改造之后新加的，却沿用方形的「中心 + 四角」取样。
`footprint_from_control()` 对圆返回 `(radius, radius)`，四角落在 `√2 × 0.1175 = 0.166 m`，
再和写死的 `prefix_margin_m = 0.10` 比较：

| | 等效要求的过道净宽 |
|---|---|
| 改之前 | `2 × (0.1175 + 0.10)` = **0.435 m** |
| 圆盘真实需求 | `2 × hard_clearance` = `2 × 0.172` = **0.344 m** |

`score_trajectories_by_ESDF` 早就是 `if is_circle: n_along = n_across = 1`，其 docstring
甚至写明「按外接方形取样会让角点远出 41%」—— 同一个错在同一个文件里修过一次，新函数又犯。

实测夹点净宽 **0.40 m**，正好卡在两个数之间。放行的前进轨迹 **6/90 → 30/90**。

`_worst_footprint_point` 有一模一样的错（其注释还声称「取样铺满方式和
score_trajectories_by_ESDF 一致」），一并改成圆盘取中心。

## 2. 障碍势垒在 soft 边界上是断崖，量纲差 1 万倍

内核软代价 `decay / (d − hard + 1e-3)`，planning_node 再乘 `100000`：

| 整条轨迹最小净空 d | 障碍项 | 参照：多推进 1 m |
|---|---|---|
| 0.273（刚出 soft=0.272） | 0 | 100 |
| 0.272（刚进 soft） | **990 000** | 100 |

只要车离障碍不到 0.272 m，**静止轨迹净空最大 ⇒ 站着不动是全局最优**。
实测前 5 名候选全是 `vx=0` 且 `obst=0`。

改成在 soft 处连续归零、往 hard 发散：

```
obst = w_obstacle × ( 1/(d − hard + 1e-3) − 1/(soft − hard + 1e-3) )
```

`TINYNAV_W_OBSTACLE` 默认 1.0。量纲：净空比 hard 多 0.03 m ≈ 少走 0.25 m。
方形底盘保持 `score × 100000` 不变。顺带修掉一个潜在坑 —— 旧量级能越过
`admissible = costs < 1e9`，被误当成「被门掉」。

## 3. 没有静止代价，而最慢那档的奖励只有 13 分

修完 1、2 之后的实测账目（目标在正前方 2 m）：

```
不动      clr=0.300  obst=0   prog=207                    = 207
最好前进  clr=0.206  obst=19  prog=194  sm=2.5  head=5.0  = 220
```

前进的**全部**奖励就是 13 分：轨迹库最慢的非零档是 `max_vx/6 = 0.042 m/s`，3 s 只推进
0.125 m。而惩罚是 19 + 2.5 + 4.5 = 26。**「慢慢挤过窄缝」恰恰是那一档存在的理由，
它却结构性地永远赢不了。**

加 `w_idle`（`TINYNAV_W_IDLE`，默认 40）：`|vx| < 1e-6` 的轨迹加一笔固定代价。原地转和
完全停住拿同一个值，因此它们内部的相对排名不变，脱困逻辑不受影响。

⚠️ **必须按目标距离渐隐**（`TINYNAV_IDLE_FREE_M`，默认 0.5 m 内归零、1.0 m 外满额）。
这个节点**故意没有到达判定** —— 到达是靠「站到前视点上 → 进展奖励消失 → 车自然停住」
实现的（见 `planning_node.py` 里 `target_dist_xy` 那段注释：x5 曾加过到达启发式，一次
227 s 的运行里误判到达 6 次、停车 138 s）。不渐隐就会把车推过前视点。

## 🔴 全局路线自己穿过障碍（2026-09-03 板上定案）

### 机制

`map_node.py:485` 一次性 `np.load(occupancy_grid.npy)`，**全文件再没有任何一处写入
`self.occupancy_map`**。全局搜索 `search_within_sdf_map_numba` 唯一的碰撞过滤是
`occupancy_map == 2`，即**建图那一刻的障碍**。建完图之后搬进来的东西，全局规划器
根本不知道。而且路线被钉在建图轨迹上（`sdf_map` 的种子是 `odom_positions`，bucket
升序展开 = 刻意的示教-复现走廊约束）。

局部这边为贴合它付 `w_path_follow = 80` 分/米，于是**贴着障碍沿路线挤过去就是代价
函数的全局最优解**：

```
势垒 = 1/(d-0.172+0.001) - 1/0.101     w_obstacle = 1.0
d(圆心)  车壳净空   势垒   ≈ 值多少米绕行
0.272     15.0cm    0.0      0
0.220      9.8cm   10.5      0.13 m
0.200      7.8cm   24.6      0.31 m
0.185      6.3cm   61.5      0.77 m
0.175      5.3cm  240.1      3.00 m
```

→ **要买到 0.8 m 绕行，沿路线那条必须先挤到车壳 6.3 cm。** 势垒在 8 cm 之外几乎是平的，
绕行代价是线性的，所以它的最优策略天生是贴着走。

### 实测（`decision:` 新增 `route_block` / `route_clear` 两字段，未暂停 710 拍）

| 全局路线状态 | 拍数 | `esdf_at_robot` 中位 | 跑满 0.4 占比 | 可行前进中位 |
|---|---|---|---|---|
| 安全 `route_clear` ≥ 0.17 | 382 | **0.56 m** | 64% | **85/90** |
| 擦边 0.05~0.17 | 253 | **0.27 m** | 32% | **26/90** |
| 埋进障碍 < 0.05 | 72 | 0.29 m | 35% | 36/90 |

**`route_clear` 低于碰撞门限的占比 46%。** 那一趟 3 次真碰撞（`esdf_at_robot < 0.172`）
和 17 次全速贴着走（`esdf<0.22` 且 `vx≥0.30`）**全部**落在后两档里。
🔑 路线安全时车又快又稳，一次没出事 —— **所以主因是路线，不是速度、不是量化误差。**

### 修法：`TINYNAV_ROUTE_UNPIN_ON_BLOCK`（默认 1 = 开）

```
route_clear < hard_clearance  →  本拍 w_path_follow = 0
```

阈值不是调出来的，就是碰撞门限本身 —— 上面那张表的分界点。日志打 `ROUTE-UNPINNED`。

🔴 **只清 `w_path_follow`，不清 `w_route_progress`。** 整条路线丢掉（`has_route=False`）
会退回贪心终点距离，那正是 PR #226 的路线打分修掉的绕角抖动（doorway 138 次变向 → 0）。
进展项按"沿路线还剩多远"算，不在路线上的格子继承最近路线格的剩余量，所以让开之后
它仍然朝目标走。

### ⚠️ 这个修法的上限

进展项仍然指着**那条穿墙的路线**。所以"路线指向一扇已经堵死的门、真正的通路在旁边
1.4 m"这种情况解钉救不了 —— 那需要**全局重规划吃实时障碍**（map_node 订
`/planning/obstacle_mask`，按 map→odom 投进 `occupancy_map` 再搜）。
场景 `route_thru_blocked_door` 就是这条上限的探针。

# 代价函数全貌（2026-09-04 从代码抄下来的现役版本）

选择就一行：`np.argsort(costs, kind='stable')[:1]` —— 取代价最小的那条。轨迹库 110 条（`blocked=xx/110`），前进 90 条（`fwd_ok=xx/90`）。

```
cost = ob + prog(+terminal) + path + smooth + gate + head + idle
```

| 项 | 权重（env 开关） | 公式 | 它到底在管什么 |
|---|---|---|---|
| **`ob` 障碍势垒** | `TINYNAV_W_OBSTACLE=1.0` | 碰撞 → `inf`；否则 `1/(max(d,hard)−hard+1e-3) − 1/(soft−hard+1e-3)`，`d ≥ soft` → 0 | `d` = 整条轨迹的最小净空。**🔴 不含起点**（`TINYNAV_BARRIER_INCLUDE_START=0`）—— 含起点时 110 条候选共用同一个起点，势垒退化成常数，一条也区分不出来 |
| **`prog` 沿路线剩余** | `TINYNAV_W_ROUTE_PROGRESS=100` | `100 × end_remainings[idx]` | 轨迹终点**沿全局路线**还剩多远。**不是直线距离** —— 直线距离在绕障时是局部极小 |
| `terminal` 终点吸引 | `TINYNAV_W_GOAL_TERMINAL=100` | 仅当 `end_remainings < 0.5`（`ROUTE_TERMINAL_BAND`）：`100 × ‖终点−目标‖` | 快到了才按直线收敛 |
| **`path` 贴合路线** | `TINYNAV_W_PATH_FOLLOW=80` | `80 × path_costs[idx]` | 轨迹离全局路线最远多少。⚠️ **路线被判堵时（`ROUTE-UNPINNED`）这一项置 0** |
| `smooth` 连续性 | 写死 40 / 10 | `40×|Δvx| + 10×|Δω|` | 相对上一拍指令的跳变 |
| **`gate` 硬门** | — | 0 或 **1e9** | 见下 |
| **`head` 朝向** | `TINYNAV_W_HEADING=20` | `20 × |终点车头朝向 − 终点到目标的方位|` | 对位移轨迹几乎不变；**对原地转是唯一有意义的判据** |
| **`idle` 静止惩罚** | `TINYNAV_W_IDLE=40` | `40 × idle_scale`，当 `|vx| < 1e-6`（`IDLE_VX_EPS`） | `idle_scale = clamp((目标距离 − 0.5)/0.5, 0, 1)`，即离目标 <0.5 m 时不罚站着（`IDLE_FREE_M`） |

**没有全局路线时**（`has_route=False`，或 `TINYNAV_ROUTE_COST=0`）：`prog` 换成 `100 × ‖轨迹终点 − 目标‖`（**只算 xy**，目标带着约 0.7 m 的相机高度，`sqrt(dxy²+0.7²)` 会把近目标处的排名压平），`path = 0`。

## `gate = 1e9` 的三条规则（`_motion_gate_penalty`）

| 动作 | 规则 | 为什么 |
|---|---|---|
| **倒车** | 只有 `front_blocked and allow_reverse` 才放行 | 占据栅格**只由前向射线写**，车后方的格子相机从没看过 → 倒车轨迹"无碰撞"是假的。2026-08-10 实测 40 s 的 `vx=-0.2` 直接撞上去 |
| **原地转** | 永远放行，不受前方探针门限约束 | 它的扫掠体积相机已经看过了。⚠️ 前提是**碰撞圆的圆心就是旋转中心** —— 驱动轮后移 20 mm 后 `collision_radius=0.1375` 取的是绕驱动轴的扫掠半径；谁改回盘半径这条豁免就静默变错 |
| **前进** | `forward_ok[idx]` = 该轨迹前缀净空 ≥ `v × reaction_time_s(2.0)` | 从"承诺一条轨迹"到"能改指令"之间车会走这么远 |

## 怎么读 `candidates:` 那行

```
vx=+0.400 w=-0.100 clr=0.312 obst=0 prog=1250 path=240 sm=0.0 gate=0e+00 head=8.4 idle=0 = 1498
```
分项就是上表的顺序。**要横向比同一行里的分项**，不要跨行比总分 —— 势垒和 gate 的量纲差 1e9。

🔴 **不要离线复算代价函数**（见上文 §「不要离线复算」）：内部 ESDF 和发布出去的 `obstacle_mask` 不是同一份，复算必然对不上。分项已经打在日志里了，直接读。
