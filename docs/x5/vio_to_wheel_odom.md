# 用轮速里程计换掉 VIO：CPU 账、唯一的阻碍、迁移步骤

> 2026-09-01。动机是 CPU：板上 8 核，导航时实测已占 ≈480%，而单个最大消费者是相机固件。
> 结论：**可行，但有一个必须先补的洞（姿态），而且必须先跑完一次基线导航再动。**

## 1. CPU 账（10 秒 `/proc` jiffies 差分，不是 `ps` 的 pcpu）

| 进程 | CPU | 干什么 |
|---|---|---|
| **`insight_full`** | **252.6%** | 相机固件：**深度 + VIO 在同一个进程** |
| `looper_bridge_node` | 97.3% | 话题转发 / 关键帧同步 |
| `uvicorn` | 50.4% | web 后端 |
| `planning_node` | 46.2% | 避障 + 规划 |
| `diffcar_control` | 19.3% | 串口 |
| `cam-service` | 13.6% | |
| **合计** | **≈480% / 800%** | load average 6.78 |

`insight_full` 一家 2.5 个核。固件源码我们有（LooperHub），**而且有 `vio_enabled` 开关**
（曾经改过但没部署）。

⚠️ **但 252.6% 里 VIO 占多少是未知的** —— 深度和 VIO 同进程，只有真部署一次
`vio_enabled=0` 的固件才能分开。乐观估计能省 1~1.5 核（VIO 本体 + bridge 里同步/转发 VIO
位姿的那部分）。**这是第一步，也是决定后面值不值得做的唯一依据。**

## 2. 🔴 唯一的技术阻碍：姿态，不是位置

`low_obstacle_hits` 是在**世界系**里用完整位姿 `T` 变换点云的 —— 相机的俯仰/横滚由 VIO 提供。
轮速里程计只有平面 (x, y, θ)，`wheel_odometry_node` 发出的相机位姿**俯仰/横滚恒为零**。

实测数字说明它多要紧：

```
车身固有俯仰                    −1.38°（两块不同地面重复到 0.24° 内）
VIO 姿态 vs 真实地面（现状）      0.80°
丢掉 VIO、硬编码机械俯仰          约 1.4°
  → 矮障碍量程 1.5 m 处 1.5×sin(1.4°) = 37 mm，门限 low_obs_h_lo = 50 mm
  → 余量从 2.4 倍 掉到 1.35 倍；上坡/过门槛/载荷变化时完全失效
```

### ✅ 正解：用深度图自己拟合地面平面代替 VIO 姿态

`floor_probe` 那一套已经验证过：候选点取 `Z∈(0.3,2.5) 且 Y>0.04`，RANSAC + 迭代
3×3 协方差特征分解 → **内点 87~91%、残差 RMS 5.4~5.6 mm**，几万点的成本可以忽略。
它**直接测量我们真正需要的那个量**（相机相对当前地面的姿态），比经过 VIO 转一手更直接 ——
上坡、过门槛都自动跟上。

⚠️ 实现注意：`np.linalg.svd` 必须带 `full_matrices=False`，否则会尝试分配 20 GB；
用 3×3 协方差 `eigh` 更省。

## 3. 换掉之后其他环节会怎样

| | 影响 |
|---|---|
| 重定位 | ✅ 不受影响 —— 图像检索 + PnP，与里程计源无关 |
| 现有地图 | ✅ 不作废 —— `poses.npy` 是相机位姿，`T_map_to_odom` 照样算 |
| **VIO 丢跟踪把固件卡死** | ✅ **整类故障消失** |
| bridge 丢掉 1/4 的位姿（回调组抢线程） | ✅ 也消失 |
| 航向漂移 | 🔴 实测 0.030 rad/m 系统性左偏（可标掉）+ 随机部分。重定位 96.8% 会持续纠正，但两次重定位之间的漂移变大 |
| 打滑 / 被架起 | 🔴 轮速里程计察觉不到；VIO 能。**代偿：保留 C/D 对比当检测器需要 VIO，所以这条会一起失去** |
| 尺度锚点 | 🔴 从 VIO 积分变成**深度相机的立体基线 0.1002 m**，所以轮速里程计要重标到**物理米**（卷尺），见 `odometry_vio_calibration.md` 第 2 节 |
| 要改几处 | `odomSource` / `mapOdomSource` / `keyframePoseTopic` / `controlPoseTopic` **四个开关必须一起换** |

## 4. 迁移步骤

| | 动作 | 判据 / 为什么 |
|---|---|---|
| **0** | **先跑完一次基线导航** | 当前配置刚验证到 ±0.6%，不要在没有基线的时候动架构 |
| 1 | 部署一次 `vio_enabled=0` 的固件，只为量 CPU（可回退） | 省不到 1 核就别做了 |
| 2 | 实现「深度图拟合地面平面」代替 VIO 姿态 | 唯一的技术阻碍 |
| 3 | 卷尺重标 `ppr` 和 `WHEEL_BASE`（同比例） | 参考从 VIO 换成 metric |
| 4 | 四个开关一起换，重新验证矮障碍和地面剔除 | |
