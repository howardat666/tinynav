# 圆形差速底盘设计记录

> 2026-08-28。目标从「改装现有小车」变成「给 Looper 做一个可卖的衍生品」：沿用现有电机、
> 驱动板、电池、ESP32、Looper，**底盘和脚轮重新设计并 3D 打印**。
> 源文件在 `~/桌面/3D/diff_car_round.scad`（底盘）和 `~/桌面/3D/looper2.scad`（相机支架）。

## 1. 为什么是圆形 —— 理由不是「方便调试」

现在的方形车：0.28 × 0.35，控制点在驱动轴（车体中心前 0.04）。

```
原地转扫掠半径 = sqrt(0.18² + 0.175²) = 0.251 m
车体半宽                              = 0.175 m
```

**所以「原地转」在方形车上是一个可能撞的动作。** 于是必须逐位姿做足迹碰撞检查、可能被全部
否掉、否掉后只剩倒车、倒车又没有后方障碍图 —— 楔住、摆头、倒车 36 秒这一整类问题都是
这一件事的下游。

**圆盘 + 驱动轴过圆心之后这条链整体消失，而且是可证明的**：圆绕自己圆心旋转，占据区域完全
不变。当前位姿不撞 ⇒ 任意角度的原地转都不撞。

顺带的白拿收益（CPU 是板上的第一约束，导航前已 7.67/8 核）：

| | 方形 | 圆 |
|---|---|---|
| 每个位姿的碰撞检查 | 20 个足迹取样点 | **1 次 ESDF 查表** |
| 每周期总查表 | 110 条 × 31 位姿 × 20 = 68,200 | **3,410** |
| 欠采样风险 | 有（闸门 5 点 vs 内核 20 点不一致） | 无，圆的判据是精确解 |

⚠️ **驱动轴每往前偏 1 mm，碰撞半径就 +1 mm** —— 差速车的原地旋转中心固定在驱动轴中点，
圆形碰撞模型的圆心必须取那一点。所以 `control_x = 0` 不是可选项。

## 2. 三条推导出来的设计定律

### 2.1 盲区恒等式：相机往前挪是纯赚的

相机不能看到自己的盘沿，约束是

```
(光心高 − 板面高) / tan(垂直半视场)  ≥  盘半径 − 光心y
```

每个方案都取**刚好满足**这条的最低相机高度，代回盲区式 `盲区 = 光心y + 光心高/tanθ − 盘半径`，
`光心y` **完全约掉**，盲区恒为常数（本设计约 64 mm）。

→ 相机往前挪，盲区不变，但**光心能低很多、支架能短很多**。

| 光心 y | 最低光心高 | 竖板高 | 整车高 |
|---|---|---|---|
| 0（正中） | 159 | 119 | 177 |
| +65（当前） | 111 | 71 | 128 |
| +85（最前） | 92 | 52 | 110 |

🔴 **「相机放在旋转中心最好」这个说法要收窄**：它的理由是**标定方便**（360° 闭合法要找
「相机回到同一位姿」那一帧，偏心画圆会干扰）。对运行时，**纯旋转是视觉惯性里程计的退化
情况**（无平移即无视差无深度），相机偏心在原地转时给出真实平移，**反而略有利**。

### 2.2 脚轮干扰力矩 `M = μ·W·a`，臂长约掉

设总重 W、重心在驱动轴后 a、脚轮销轴在驱动轴后 L、摩擦系数 μ：

```
脚轮垂直载荷      F = W·a/L
横向搓动摩擦力    f = μF
对偏航的干扰力矩  M = f·L = μ·W·a      ← L 约掉了
```

→ **减小脚轮造成的航向漂移，唯一的大杠杆是重心离驱动轴的距离 a**；不是脚轮直径，也不是
臂长。漂移还正比于**偏置距 d**（它决定对正过程持续多远）。

下限来自制动时脚轮不脱地：`a > α·h_cg/g`。1 m/s² 减速、重心高 50 mm → `a > 5 mm`，
目标区取 **8~12 mm**。

这条直接解释了实测：4 米直线横偏 15 cm vs 4 cm，唯一变量是脚轮初始朝向。

### 2.3 相机在前 + 电池在后 ⇒ 重心天然贴着驱动轴

| 件 | 质量估 | y (mm) | 力矩 (g·mm) |
|---|---|---|---|
| 相机 + 支架 | 197 | +55 | **+10,835** |
| 底盘 Ø235×6 PETG | 305 | 0 | 0 |
| 两电机 + 轮 | 240 | 0 | 0 |
| 电池 100×60 横置 | 200 | −72 | **−14,400** |
| 驱动板 + ESP32 + 线 | 80 | −6 | −480 |
| 脚轮 | 30 | −88 | −2,640 |
| **合计** | **1052 g** | | **−6,685 → a = −6.4 mm** |

**两个主力矩量级相当**，所以不管脚轮放前放后，余量都只有几毫米。

| | 后脚轮 | 前脚轮 |
|---|---|---|
| 重心要求 | 轴**后** 8~12 | 轴**前** 8~12 |
| 电池位置 | 横置 (0,−72)，已在后极限 | 得前移到约 (0,−8) |
| 结果 | −6.4 mm，需电池 ≥270 g | +7 mm |
| 走线槽 | **能放中间** | 只能放侧面（电池前移会压住中间） |

**装配时必须真的称 Looper / 电池 / 电机的重量**，这是唯一还悬着的输入。

## 3. 尺寸与坐标（原点 = 圆心 = 驱动轴中点，+Y 车头）

| 项 | 值 | 依据 |
|---|---|---|
| 圆盘 | **Ø235 × 6**，PETG/ASA 不用 PLA | 整块打进 256 床留 10 mm；**不拼接**（轮距是烧进固件的常量，螺接件的轮距取决于装配扭矩）。PLA 在 40 °C 以上蠕变，标定会无声失效 |
| 轮距 | **210** | 轮外沿 117.5 = 盘沿 → 碰撞半径就是盘半径 |
| 轮罩缺口 | x ≥ 89.5，y = ±35.5，内角 R4 | 轮子是 Y/Z 向 Ø65、X 向 25 的盘，**和板面共面**，必须开缺口 |
| 电机孔 | 左 (−80, −48.455) (−80, +9.545)；右 (80, −9.545) (80, +48.455)，Ø3.3 + 90° 沉头 | 见 §4 |
| 相机支架 | 4× Ø3.3 @ (±44, +29) (±44, +61) | 两排：一排两孔是条铰链线，支架会前后点头 |
| 驱动板 | 4× Ø3.0 间距 44×44 @ (56, −6)，Ø6.5 立柱高 5 | 右 |
| ESP32 | 60×32 放平 @ (−54, −5)，刻线 | 左。竖放的话 60 长必然顶到支架底板 |
| 走线槽 | 一条 40×24 @ (0, 0)，R3 圆角 | 相机整组在前，中间空出来了 |
| 电池 | 100×60 横置 @ (0, −72)，魔术贴 | 它是把重心压到轴后的主要配重 |
| 脚轮 | (0, −88) 实施；(0, +88) 对照，各 45×45 刻线 + 十字 | 选型后现场钻，螺钉头要沉进去 |

相机支架 `looper2.scad`：底板 **110 × 44 × 4**（和竖板同宽，否则竖板两侧只有一条 4 mm 的线
贴打印床，必翘边），竖板 110 × 71 × 4，**两条向后的全高翻边** x = ±30 深 18，
M3 × 4 @ (±44, ±16)，相机孔 Ø3.8 间距 95、离底板 55（沿用 `looper.scad` 原值）。

**翻边不是装饰**：竖板 71 高、端部挂 197 g，4 mm 平板截面惯性矩只有 587 mm⁴，一阶弯曲约
**15 Hz**，正落在底盘振动带里、会直接进 VIO 的惯性测量单元。加翻边后 I = 22,800 mm⁴
（×39），约 **92 Hz**。三角筋只管根部那一小截，翻边整根都在。

## 4. 电机孔型的真值（曾推错一次）

🔴 我曾从「孔在 |x|=90 + 实测轮距 320」反推出 `motor_arm = 70 mm`，**错了**（实测 25）。
那条推理链断在「旧车轮距是靠横向加长件撑出来的」这件事上。

孔型真值，与 `diff_car.scad` 完全自洽（两侧反推出的输出轴都是 60.545）：

```
输出轴夹在两孔之间，一边 9.545、一边 48.455，合计 58
左侧孔组靠后，右侧靠前
```

**这个前后错开是原厂设计的**：原厂轮距只有约 120，孔线在 |x|=35、轴在 60，两个电机机体会在
中间撞上 —— 靠前后错开 38.91 mm 让它们错身而过。我们轮距 210、孔线在 80，机体各占
|x| 25..80 本来就不撞，但这个偏置是电机自带的、不可调。

## 5. 换圆形后要跟着改的软件

| 参数 | 从 | 到 |
|---|---|---|
| `DIFFCAR_CONFIG.shape` | `square` | `circle` |
| `radius` / `collision_radius` | — | **0.1175** |
| `control_x` | 0.04 | **0** |
| `safety_radius` | 0.1 | **先试 0.05** |
| 固件 `WHEEL_BASE` | 0.3234 | 重标（轮距 0.32 → 0.21） |
| 固件 `WHEEL_CIRC` | 0.2173 | 重标（轮实测 Ø65，不是 Ø70） |
| `obstacle.robot_z_bottom/top` | −0.30 / 0.40 | 按新光心高度平移，保持绝对波段不变 |

⚠️ `safety_radius` **必须重定**：圆形的硬碰撞门限是 `半径 + safety_radius`，0.1 的话门限
0.2175，而 0.5 m 门洞的中线 ESDF 只有 0.25，余量剩 33 mm。圆的碰撞判据是精确解，不需要靠
余量去补方形那 20 点取样的漏洞。

轮距重标用 `tool/x5_board/diffcar_spin_closure.py`（转满 360° 找视差过零那一帧，不占地面空间）。

## 6. 反复踩的两个坑

- 🔴 **干涉检查必须写脚本遍历，不能用眼睛看。** 漏过两次：走线槽吞掉左侧电机孔（只查了右边，
  而左右孔组是前后错开的）、支架底板加宽后压住驱动板和 ESP32。现在的检查覆盖
  「每个孔 × 每个开口」「每个孔到盘沿/缺口的边距」「孔与孔净距」「件两两重叠」
  「件的角是否掉出圆盘或缺口」「相机视场里有没有自身部件」。
- 🔴 **轮子的朝向**：Y/Z 向 Ø65、X 向 25，和板面共面。按「X 向 65 长」算缺口会差一倍。
  共面 ⇒ 必须开缺口；改成「电机贴盘沿、轮子全在盘外」会把整机撑到 **Ø368，比现在的方形车
  还宽**，是净退步。
